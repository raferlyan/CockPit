## Cockpit v0.5.0

这一版主要解决两件事：受保护目录上传时，看不出是没有 root 还是分区没 remount；需要输入密码或解挑战码的设备，root 只能在终端里手动操作。新增了右键进入 root（四种方式）和本机终端，上传也有了分步进度。

### 新功能

#### 右键设备进入 root
在左侧设备列表里右键设备：
- **进入 root**：使用默认方式，或这台设备单独指定的方式。成功后设备标记变成绿色的 **root**，文件传输、目录浏览、存储统计、日志导出都会通过这个后台 root 通道执行。
- **临时换一种方式**：这次改用另一种方式，不改设置。
- **打开 root 终端**：新开一个 Shell 标签并自动完成 su，过程直接显示在终端里；失败时终端里会写明原因。
- **退出 root**：结束 root 通道；通过 adb root 进入的执行 `adb unroot`。
- **root 方式设置…**：设置里的「root 方式…」也能打开。

支持四种方式：
- **su（免密）**：适用于 Magisk、KernelSU、userdebug 自带的 su。
- **adb root**：适用于 userdebug / eng 版本，adbd 以 root 重启。
- **用户名 + 密码**：su 后自动填入保存的密码。密码用系统钥匙串（Windows DPAPI / macOS 钥匙串）加密保存在本机，界面上不显示。
- **解密工具**：执行 su → 读出挑战码 → 交给电脑上的解密工具（如 `decrypt.exe`）→ 取工具输出的最后一行作为密码填入。
  - 挑战码默认作为参数传入，也可以用 `{challenge}` 指定位置，或改为写到标准输入。
  - 挑战码自动识别，识别不准时可以填正则。
  - 设置里可以粘贴一个挑战码，先试运行工具。

su 失败时会说明卡在哪一步，并附上 su 最后的输出，例如「su 再次要求输入密码：解密工具算出的密码不对」「su 要求输入密码：请在 root 方式里改用密码或解密工具」「该设备不支持 adb root」。

#### 本机终端
终端区新增 **+ 本机终端**，Windows 上显示为 **+ PowerShell**，macOS / Linux 上是登录 shell。Cockpit 使用的 adb 所在目录已加入 PATH，直接敲 `adb` 即可。本机终端不受设备断开影响。

### 改进

#### 文件上传：分步进度和明确的失败原因
- 点上传后立即显示进度区，依次显示：检查目标目录 → 获取 root（提示在设备上点允许）→ 字节进度、速度和剩余时间 → 用 root 写入目标位置。全程显示已用时间，没有字节进度的步骤用滚动条表示仍在进行，不会看起来像卡住。
- **发送数据前先检查目标目录**：能否写入、所在挂载点是否只读、adbd 是否 root、su 能否使用。写不进去时立即失败，不再先把整个文件传完才报错，并区分以下情况：
  - **分区只读，但拿得到 root**：提示需要 remount，并提供「remount <挂载点> 后重试」按钮，一键重新挂载为可写并重新上传。adbd 是 root 时用 `adb remount`，否则经 root 执行 `mount -o rw,remount`；受 verity 保护的设备会提示需要 `adb disable-verity` 并重启。
  - **分区只读，也没有 root**：说明两者都缺，并分别说明 userdebug 和 user 版本怎么处理。
  - **分区可写但没有权限，也没有 root**：建议进入 root，或改传到 `/sdcard`、`/data/local/tmp`。
- 失败原因常驻显示在传输窗口里，不再只靠一闪而过的通知。

#### root 状态标记
- 在终端里手动 `su` 只会让那一个终端变成 root，设备标记显示为黄色的 **root**，悬停时说明其它功能仍是普通身份。
- 通过右键「进入 root」后，标记显示为绿色的 **root**，并注明使用的方式。

#### 使用向导
新增「进入 root」一步；文件传输和终端两步更新为新的说明。

### 问题修复

- **adbd 已是 root 但分区没 remount 时，上传误报「设备没有可用的 su」**：现在会正确提示需要 `adb remount`。
- **没有 su 的设备往受保护目录上传时，先把整个文件传到临时目录才报错**：现在发送数据前就会说明原因。
- **root 中转时进度条停在 100% 不动**：现在显示「正在用 root 写入目标位置」。

### 其它

- 新增 su 交互（免密 / 密码 / 挑战码 / 密码错误 / su 不存在）、root 通道、解密工具调用、root 设置存储、挂载表解析和上传预检的单元测试（共 155 个测试）。
