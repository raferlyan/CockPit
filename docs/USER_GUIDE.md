# Cockpit 使用说明

> 适用版本：0.1.x · 更新于 2026-11-02 · 支持 macOS 与 Windows

## Cockpit 是什么

Cockpit 是一个给 Android 开发、测试和系统调试同学用的桌面工具，**把平时要开好几个窗口做的事收到一个窗口里**：

| 以前 | 现在用 Cockpit |
|---|---|
| scrcpy 开一个窗口投屏 | 投屏嵌在主窗口，最多 4 台同时投 |
| 终端里敲 `adb -s <序列号> shell`，多台设备要记序列号 | 选中设备点「+ Shell」，标签上直接显示设备名和序列号 |
| `adb shell top`、`dumpsys battery`、`cat /sys/class/thermal/...` 轮着看 | CPU、内存、温度、电池、网络、进程、存储每秒刷新，带 5 分钟曲线 |
| `adb push` / `adb pull` 手敲路径 | 拖文件进来，选好设备目录就能上传；设备上的文件点一下就能下载 |
| 串口工具另开一个软件 | 同一个终端区里开串口标签 |

只依赖电脑上的 adb，不需要在手机上装任何 App。

## 界面一览

```
┌──────────┬───────────────────────────────────┬──────────────┐
│          │                                   │  设备信息     │
│  设备列表 │   中间区域                         │  （固定）     │
│          │   · 默认：设备状态（负载、曲线、进程）│  投屏 / 文件传输│
│          │   · 点「投屏」后：投屏画面           ├──────────────┤
│          │                                   │  设备状态     │
│          ├───────────────────────────────────┤  （投屏时出现，│
│ 无线连接  │   终端：Shell / Logcat / 串口 多标签 │   可滚动）    │
└──────────┴───────────────────────────────────┴──────────────┘
```

- **默认看状态**：打开应用、选中设备后，中间区域显示这台设备的实时负载。
- **需要时再投屏**：点右侧的「投屏」，投屏画面换到中间，设备状态挪到右侧下方继续刷新。点投屏区右上角的「收起投屏」回到状态视图。
- **设备信息固定**：右侧上方的序列号、型号、Android 版本等始终可见，只有下面的设备状态会滚动。
- **主题**：底部状态栏右侧可切换「白天 / 黑夜 / 自适应」。自适应跟随系统的深浅色设置，选择会被记住。
- **收起区域**：设备列表、右侧设备信息和底部终端的标题栏右边都有收起箭头，收起后变成贴边的图标条，点图标条展开（类似 Android Studio 的工具窗口），收起和展开带弹性过渡动画。快捷键 ⌘1 / ⌘2 / ⌘3 分别切换这三个区域（Windows 为 Ctrl），⌘⇧F12 一键收起或展开全部。终端收起时会话不会断开。

## 快速开始

1. **装 adb**：安装 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)。Cockpit 会自动在 `ANDROID_HOME`、`PATH` 和 SDK 默认位置里找 adb，底部状态栏会显示找到的路径。
2. **装 Cockpit**：到 [Releases](https://github.com/raferlyan/CockPit/releases/latest) 下载安装包。
   - macOS 首次打开被拦截：Finder 里右键 Cockpit →「打开」。提示“已损坏”时在终端执行 `xattr -cr /Applications/Cockpit.app`。
   - Windows 出现 SmartScreen：点「更多信息」→「仍要运行」。
3. **连设备**：手机打开「开发者选项 → USB 调试」，插上 USB，在手机上点允许。左侧设备列表出现绿点即为在线。
   - 无线调试：在左下角输入 `IP:端口`（如 `192.168.1.10:5555`）点「连接」。

## 功能说明

### 设备状态

选中在线设备即开始采集，每秒刷新：

- **概览卡片**：CPU 总占用和负载均值、内存（含 Swap/ZRAM）、CPU/GPU/机身温度、电池电量与充电状态、网络上下行速率。
- **曲线**：最近 5 分钟的 CPU 与内存占用、温度变化。
- **各核心**：每个核心的占用和当前频率，离线核心会标出来。
- **进程 Top 10**：按 CPU 排序，鼠标悬停显示 PID 和用户。
- **存储**：各分区已用 / 总量 / 剩余。点分区可以逐层进入，查看每个子目录和文件的占用（按大小排序，带占比）；也可以点 `/sdcard` 等快捷目录或直接输入路径。没有读取权限的目录在有 su 的设备上可以「用 root 重新统计」。每个目录右侧的 `>_` 会新开一个 Shell 标签并进入该目录。

连接了多台设备时，标题右侧可以切到「对比」，把 2~3 台设备的 CPU、内存或温度画在同一张图上。

### 投屏与操控

点右侧「投屏」立即开始，不用再点第二次。

| 操作 | 效果 |
|---|---|
| 鼠标左键 | 触摸、滑动 |
| 鼠标右键 | 返回（息屏时点亮屏幕） |
| 鼠标中键 | 主页 |
| 滚轮 | 滚动 |
| 键盘 | 直接打字，中文输入法可用 |
| Cmd/Ctrl + C / V | 设备与电脑之间复制粘贴 |
| 工具栏 | 返回、主页、多任务、音量、电源、通知栏、旋转 |

- **多台同时投屏**：右上角「+ 添加设备」，最多 4 台。可在「网格」（并排）和「单台」之间切换，切换时其它设备的投屏不会中断。
- **拖文件到投屏画面**：会打开文件传输窗口，并带上这些文件。
- 投屏区标题显示设备名和序列号，多台同型号设备也不会认错。

### 终端（Shell / Logcat / 本机终端 / 串口）

终端区右上角：

- **+ Shell**：对当前选中的设备打开 `adb shell`，支持 Tab 补全、Ctrl+C、vi、top 等交互程序。
- **+ Logcat**：可以先填启动参数，如 `-b crash`、`-s ActivityManager`。打开后标签上方有筛选栏（见下文）。
- **+ 本机终端**（Windows 上显示为 **+ PowerShell**）：电脑本机的终端，Windows 是 PowerShell，macOS / Linux 是登录 shell。Cockpit 用的 adb 所在目录已加到 PATH，直接敲 `adb` 即可。
- **+ 串口**：通过 USB 转串口线连接设备调试串口，不需要 adb。可以设置波特率、数据位、校验、停止位、流控和换行符。

**标签**显示「设备名 · 类型 · 序列号」，鼠标悬停可看完整序列号；`$` 表示普通用户，`#` 表示 root。在 Shell 里手动 `su` 只让这一个终端变成 root，设备列表上显示黄色的 **root** 标记；文件传输等其它功能仍是普通身份，需要的话用下面的「进入 root」。设备断开后标签会划掉，点「重新连接」原地重开。

终端字体在「设置 → 终端字体」里单独设置，默认是 Windows Terminal Preview 的默认字体 Cascadia Mono（随应用打包，macOS 上同样可用）。

#### Logcat 筛选与导出

Logcat 标签上方的筛选栏，修改后立即对已缓存的日志重新筛选（最多缓存 10 万行）：

| 控件 | 作用 |
|---|---|
| V D I W E F | 最低级别，如选 W 只看警告、错误和致命错误 |
| Tag | 空格分隔，Tag 包含任一词即显示；`-chatty` 这样以 - 开头的排除 |
| 关键字 | 匹配整行，命中处反色高亮；写成 `/.../` 按正则匹配，`Aa` 切换区分大小写 |
| 包名或 PID | 只看某个应用的日志；应用重启换了进程号会自动跟上 |
| 暂停 / 继续 | 暂停滚动方便查看，新日志照常缓存 |
| 清空 | 清掉已缓存的日志 |
| 导出全部 / 导出筛选结果 | 保存为文本文件，可选择保存位置 |

#### 命令智能提示

在 Shell 或串口里输入命令时，光标下方会弹出候选：

- **命令和子命令**：`am`、`pm`、`dumpsys`、`settings`、`input`、`wm`、`svc`、`cmd`、`logcat` 等常用命令及其子命令，每项带中文说明。
- **选项和参数**：如 `pm list packages -3`、`logcat -b crash`、`input keyevent KEYCODE_HOME`、`getprop ro.build.version.sdk`。
- **包名**：在 `am force-stop`、`pm clear`、`monkey -p`、`dumpsys meminfo` 等位置会提示设备上已安装的应用。支持模糊匹配，输入 `tencent` 就能找到 `com.tencent.mm`。
- **历史命令**：以前执行过的命令排在最前面（标「历史」）。

| 按键 | 作用 |
|---|---|
| Tab 或 → | 采用选中的候选 |
| ↑ / ↓ | 在候选间切换 |
| Esc | 关闭提示（之后 ↑↓ 恢复为 shell 的历史命令） |
| Enter | 执行当前输入的内容（不会自动采用候选） |

没有弹出提示时，Tab 仍是 shell 自带的补全。

#### 复制、粘贴

| 操作 | macOS | Windows |
|---|---|---|
| 复制选中文字 | Cmd+C，或选中后按 Ctrl+C | Ctrl+Shift+C，或选中后按 Ctrl+C |
| 粘贴 | Cmd+V 或 Ctrl+V | Ctrl+V 或 Ctrl+Shift+V |
| 全选 | Cmd+A | 右键菜单 |

鼠标拖动选中文字后，也可以**右键**选择「复制 / 粘贴 / 全选 / 清屏」。没有选中文字时 Ctrl+C 仍然是中断当前命令。

#### 拖文件进终端

把电脑上的文件或文件夹拖进 Shell / 串口终端，会在光标处插入它们的**绝对路径**（含空格时自动加引号），方便拼命令。

### 进入 root

在左侧设备列表里**右键设备**：

- **进入 root**：用默认方式（或这台设备单独指定的方式）进入 root。成功后设备标记变成绿色的 **root**，之后文件传输、目录浏览、存储统计、日志导出都通过这个 root 通道执行。
- **临时换一种方式**：这次用另一种方式进入，不改设置。
- **打开 root 终端**：新开一个 Shell 标签，自动完成 su（包括输入密码、跑解密工具），su 的过程直接显示在终端里；失败时终端里会写明原因。
- **退出 root**：结束 root 通道；通过 adb root 进入的执行 `adb unroot`。
- **root 方式设置…**：选默认方式、这台设备的方式和各方式的参数。设置里的「root 方式…」也能打开。

四种方式：

| 方式 | 适用 | 过程 |
|---|---|---|
| su（免密） | Magisk、KernelSU、userdebug 自带 su | 执行 su 直接得到 root |
| adb root | userdebug / eng 版本 | adbd 以 root 重启，之后所有 adb 命令都是 root |
| 用户名 + 密码 | su 后要求输入密码的设备 | 自动填入保存的密码；用户名留空表示 root |
| 解密工具 | su 后给出挑战码的设备 | 执行 su → 读出挑战码 → 交给电脑上的解密工具 → 取工具输出的最后一行作为密码填入 |

**解密工具的要求**：能在命令行运行，把密码打印到标准输出（前面有提示文字没关系，只取最后一行；`password: xxx` 这种也能识别）。挑战码默认作为唯一的参数传入，也可以在「参数」里用 `{challenge}` 指定位置（如 `-c {challenge}`），或勾选「同时写到标准输入」。挑战码默认自动识别（`Challenge: xxx` 这类写法，或提示前最后一个字母数字串），识别不准时填「提取挑战码的正则」，有捕获组时取第一组。设置里可以粘贴一个挑战码点「运行」先试一下工具。

密码用系统钥匙串（Windows DPAPI / macOS 钥匙串）加密后保存在本机，界面上不会显示。

su 失败时提示里会带上 su 最后的输出，例如「su 再次要求输入密码：解密工具算出的密码不对」「su 要求输入密码：请在 root 方式里改用密码或解密工具」。

> **root 和 remount 是两回事**：`/system`、`/vendor` 等分区默认以只读方式挂载，即使已经是 root，不重新挂载（remount）也写不进去；反过来分区可写但没有 root，也会因为没权限写不进去。在电脑终端里直接 `adb push` 用的是 adbd 的 shell 身份，和应用里哪个终端 su 过无关。

### 文件传输

在右侧设备信息里点「文件传输」，或把文件拖到投屏画面上：

1. **左侧：本机文件**。拖文件进来或点「选择文件…」，每个文件显示文件名和所在目录，路径过长时省略目录开头，不会挤压右侧；可以逐个移除。
2. **右侧：设备目标目录**。三种方式选目录：
   - 直接输入路径，点「前往」；
   - 点快捷目录 `/sdcard/Download`、`/sdcard`、`/data/local/tmp`；
   - 在下方列表里点文件夹逐级进入，「↑ 上级目录」返回。
3. 点「上传 N 个文件到 …」。目录不存在会自动创建，单个文件失败不影响其它文件，结果列在窗口底部。

**从设备下载**：在目录列表里把鼠标移到文件或文件夹上，点「下载」，选择电脑上的保存目录即可；完成后可以点「打开所在目录」。

上次使用的设备目录会被记住。

**上传过程中随时可以取消或关闭窗口**（关闭前会确认）。设备 30 秒不接收数据会自动中止，设备断开也会自动取消，写了一半的文件会被删除。点上传后马上显示进度区：先检查目标目录（能否写、所在分区是否只读），再按需获取 root，然后显示字节进度、速度和剩余时间；经 root 中转时还有「正在用 root 写入目标位置」一步。每一步都显示已用时间，不会看起来像卡住。

写不进去时在**发送数据之前**就会说明原因，并常驻显示在窗口里：

- **分区只读，已能拿到 root**：说明需要 remount，并提供「remount <挂载点> 后重试」按钮，一键重新挂载为可写并重新上传。adbd 是 root 时用 `adb remount`，否则经 root 执行 `mount -o rw,remount`；受 verity 保护的设备会提示需要 `adb disable-verity` 并重启。
- **分区只读，也没有 root**：说明两者都缺，以及 userdebug 和 user 版本各自怎么办。
- **分区可写但没有权限、也没有 root**：建议进入 root，或改传到 `/sdcard`、`/data/local/tmp`。

### 应用管理

列出设备上的全部应用，显示首次安装和最近更新时间，可按包名、安装时间、更新时间排序。每个应用可以「打开」（拉到前台，已在运行就直接切回）、停止、清数据、停用 / 启用、导出 APK、卸载。

### 截图

截图后先弹出预览，可以：

- **保存**：存到「图片/Cockpit」，同时复制到剪贴板；
- **另存为…**：自己选位置和文件名；
- **编辑标注**：画笔、矩形、箭头、文字、马赛克，可选颜色和粗细，支持撤销（Cmd/Ctrl+Z）。

保存后窗口不会自动消失，会显示完整路径，可以「复制路径」或「打开所在目录」。

### 导出设备日志

设备信息里点「导出日志」，默认读取设备上的 `/data/logger`，也可以点 `/data/log`、`/data/anr`、`/data/tombstones` 等快捷目录或输入其它路径。可以按文件名筛选（空格分隔多个关键词，支持 `*` `?` 通配）、勾选部分文件，或「导出整个目录」，导出到自己选择的电脑目录。需要 root 的目录在有 su 的设备上会自动经 su 读取。

### 操作日志

点底部状态栏的「操作日志」，右侧滑出面板，列出每次操作（上传、下载、进入 root、截图、安装应用、投屏、打开终端等）执行的 adb 命令：

- 每条显示时间、设备、耗时和成败，失败时显示原因；命令前的 `#` 注释说明用途（如「上传前检查目标目录」「root 会话中执行」）。
- 命令已按 shell 规则加好引号，可以单条复制、复制整条操作或「复制全部」，粘贴到终端里直接执行。
- 支持搜索、按设备筛选、只看失败、清空。长的内部脚本默认折叠，点「展开」查看。
- 后台的状态采集不会记录；su 时输入的密码不会出现在日志里。最多保留最近 300 条，关闭应用即清空。

### 界面语言

「设置 → 语言 / Language」切换简体中文和英文，立即生效，不会中断投屏和终端。

### 录制与分析 Trace（Perfetto）

在右侧设备信息里点「录制 Trace」，用设备自带的 perfetto 录制系统 trace（需要 Android 10 及以上），手机上不用装任何东西：

| 预设 | 内容 | 适合 |
|---|---|---|
| 卡顿 / 流畅度 | CPU 调度与频率、渲染和输入的 atrace、SurfaceFlinger 帧时间线（Android 12+） | 复现卡顿、掉帧 |
| 应用启动 | 同上，开始录制后自动强制停止并冷启动所选应用 | 启动耗时、主线程阻塞 |
| 内存 | meminfo / vmstat、各进程内存曲线、低内存查杀（LMK） | 内存上涨、后台被杀 |
| 功耗 | 电池电量与电流、Power Rails、CPU 频率与休眠、唤醒与挂起 | 耗电、发热 |

- 可以设置时长、缓冲区大小、只抓某个应用的 atrace 埋点、是否同时记录 logcat。
- 录制期间默认暂停这台设备的状态采集，避免 Cockpit 自己的 shell 命令出现在 trace 里。分析卡顿或功耗时建议先停止投屏。
- 可以随时「结束录制」，已录到的部分照常保存；关掉对话框录制会在后台继续。
- 录完自动保存到「文稿/Cockpit/Traces」，并在中间区域内嵌的 Perfetto 中打开，直接缩放到实际录制的时间段。

**查看已有的 trace**：点底部状态栏的「Perfetto」打开查看器。「Trace 列表」里是录过的文件，可以打开、在 Finder 中显示或移到废纸篓；「打开 trace…」可以打开本机任意 `.pftrace`、`.perfetto-trace`、systrace / JSON 等文件。Perfetto 界面随应用一起打包，完全离线运行，trace 不会上传到任何地方。点「收起」关闭查看器并释放它占用的内存。

## 常见问题

**设备列表是空的**
看底部状态栏是否找到了 adb；手机上是否允许了 USB 调试；数据线是否支持数据传输。

**设备显示“未授权”**
在手机上确认 USB 调试授权弹窗；没有弹窗时，在开发者选项里「撤销 USB 调试授权」后重新插拔。

**投屏黑屏或没有画面**
设备可能息屏，点工具栏「电源」点亮。目前只支持 H.264 编码。

**上传到 `/data/...` 失败**
普通 adb 身份没有写权限，换到 `/sdcard` 或 `/data/local/tmp`。

**没有包名提示**
包名在第一次需要时后台读取（`pm list packages`），稍等一两秒再输入即可。

## 附：技术沙龙演示流程（约 5 分钟）

1. **开场（30 秒）**：插上手机，设备自动出现在左侧；中间直接是实时负载，右侧是设备信息。
2. **设备状态（1 分钟）**：在手机上打开一个重度应用，看 CPU 曲线、核心频率和温度变化，进程 Top 10 里能看到它冲上来。
3. **智能终端（1.5 分钟）**：点「+ Shell」，依次输入
   - `dumps` → Tab 补全成 `dumpsys`，再看子服务列表；
   - `pm clear tenc` → 弹出 `com.tencent.mm` 等包名（演示模糊匹配，按 Esc 取消，不要真的执行）；
   - `input keyevent KEYCODE_HO` → Tab → 回车，手机回到桌面；
   - 选中一段输出右键复制；从桌面拖一个文件进终端，显示绝对路径。
4. **投屏（1 分钟）**：点「投屏」，画面换到中间；鼠标操作手机、电脑打中文；状态挪到右侧继续刷新。
5. **文件传输（1 分钟）**：把一个 APK 或图片拖到投屏画面上，选 `/sdcard/Download` 上传；再从设备目录里下载一个文件到桌面。
6. **收尾**：点「收起投屏」回到状态视图；介绍下载地址和串口功能。
